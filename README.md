# KeyNest / Market

KeyNest / Market 是一个面向虚拟商品、数字资源、账号卡密等场景的在线交易平台。项目包含前台商城、用户中心、商家发布、库存卡密、自动发货、在线支付、余额体系、会员等级、投诉处理、后台管理、系统更新等功能，适合用于搭建虚拟商品交易市场、自动发卡平台或数字资源寄售平台。

项目支持买家在线购买商品，卖家发布商品并维护库存，管理员可以在后台统一管理用户、商品、订单、投诉、支付、系统配置和运行日志。

> 说明：本项目仍在持续迭代中，部署前请根据自己的服务器环境、支付接口、邮箱服务和安全策略进行检查与配置。

## 主要功能

### 前台交易功能

- 商品列表展示
- 商品详情展示
- 商品搜索与浏览
- 登录用户购买商品
- 游客购买商品
- 在线支付订单创建
- 支付成功后自动发货
- 购买记录查询
- 卡密一行一个展示
- 卡密复制与 TXT 导出
- 库存为 0 时仍可查看未下架商品详情
- 商品下架后限制访问和购买

### 游客购买与查询码

游客购买流程已增强：

- 后台可以控制是否允许游客购买
- 游客购买仅支持在线支付
- 游客购买前会提示购买风险
- 游客购买时必须填写真实邮箱
- 支付成功后系统生成 8 位查询码
- 查询码由大写字母和数字组成
- 查询码会发送到游客填写的邮箱
- 游客可在任意设备通过邮箱 + 查询码查询订单卡密
- 查询订单时直接从数据库读取订单和发货数据

该功能用于解决游客更换设备、浏览器缓存丢失、本地订单记录丢失后无法查看卡密的问题。

### 商家功能

- 发布虚拟商品
- 编辑商品信息
- 上架 / 下架商品
- 添加库存卡密
- 删除库存卡密
- 未出售库存删除时退还发布费用
- 已出售库存删除时只删除数据，不退还余额
- 查看商品订单
- 查看买家购买数据
- 自动发货
- 收款与余额记录

### 后台管理功能

后台包含完整的管理能力：

- 总览面板
- 用户管理
- 商品管理
- 订单记录
- 客户购买数据查看
- 充值提现管理
- 卡密管理
- 投诉管理
- 商家审核
- 会员等级配置
- 系统设置
- 支付配置
- 邮箱配置
- 系统更新
- 系统日志

后台订单记录中，管理员可以查看客户购买数据。批量卡密会统一显示在一个只读大文本框中，一行一个卡密，并支持复制全部数据和导出 TXT 文件。

### 投诉处理

投诉状态已调整为更明确的裁决结果：

- 买家胜
- 卖家胜

管理员可以修改投诉裁决结果，避免误点后无法更正。

### 会员等级

会员等级由后台动态配置，不再由前台写死。

后台可以配置：

- 等级名称
- 等级描述
- 排序权重
- 开通价格
- 单商品最大账号数
- 最多商品数
- 交易手续费
- 发布费 / 账号
- 是否启用
- 是否允许前台升级
- 图标样式
- 卡片样式

会员等级数据存储在独立数据库表中：

```text
kn_membership_levels
```

### 支付与资金

- 支持在线支付订单
- 支持余额记录
- 支持充值提现管理
- 支持手续费逻辑
- 支持订单状态管理
- 支持删除未支付订单
- 支持清理订单记录

具体支付接口需要在后台系统设置中配置，并根据实际支付服务商填写真实参数。

### 邮件发送

系统支持通过邮件发送游客订单查询码。

邮件功能可用于：

- 游客订单查询码发送
- 后续扩展通知类邮件

使用前需要在系统配置中正确填写邮件服务参数，例如 SMTP 或第三方邮件服务配置。

项目主要由 PHP、MySQL 和原生前端技术组成。

```text

前端：HTML、CSS、JavaScript、Bootstrap
数据访问：PDO
```

## 项目目录

```text

api/            后端 API 接口
assets/         前台静态资源
config/         安装配置和数据库配置
core/           核心类库，例如数据库、日志、邮件、存储层
public/         公开访问入口和资源副本
templates/      前台页面模板
data/           运行数据、安装锁等
logs/           系统日志目录
README.md       GitHub 项目说明文档
```

常见入口说明：

```text
/install.php          安装入口
/admin/               后台入口
/public/admin.php     后台公开入口副本
/public/admin/        后台公开目录副本
```

不同服务器的站点根目录配置不同，可能会访问不同入口。修改后台页面时，需要注意 `admin/`、`public/admin.php`、`public/admin/` 中是否存在同步文件。

## 安装步骤

1. 上传项目文件到网站目录。
2. 配置网站运行目录。
3. 访问安装入口：

```text
/install.php
```

4. 按页面提示填写数据库信息。
5. 完成安装后进入后台：

```text
/admin/
```

6. 登录后台后先检查基础设置、支付设置、邮箱设置和游客购买开关。

默认后台账号以安装流程或数据库初始化结果为准。

- 网站名称

- 是否允许游客购买

- 邮箱发送参数

## 自动发货说明

虚拟商品通常使用库存卡密进行自动发货。

基本逻辑：

1. 商家发布商品。
2. 商家添加库存卡密。
3. 买家下单并完成支付。
4. 系统扣减库存。
5. 系统将对应卡密写入订单发货数据。
6. 买家在购买记录中查看卡密。
7. 管理员可在后台订单中查看客户购买数据。

批量购买时，卡密按一行一个展示，便于复制和导出。

- 会员等级

## 版本管理与更新

项目可以使用 GitHub 进行版本管理、备份和更新分发。

建议流程：

1. 在本地开发环境修改代码。
2. 测试确认功能正常。
3. 提交代码到 Git 仓库。
4. 推送到自己的 GitHub 仓库。
5. 服务器从 GitHub 拉取最新版本。
6. 更新完成后检查配置文件、数据库和运行日志是否正常。

公开仓库中不应该包含本机绝对路径、服务器密码、数据库密码、支付密钥、邮箱授权码或真实业务数据。

如果需要使用本地自动化脚本，建议将脚本放在私有目录，不要把带有个人路径、访问令牌或账号信息的脚本提交到公开仓库。

## 后台自动更新

后台包含“系统更新”功能。

更新源可以配置为自己的 GitHub 仓库地址。

自动更新的一般流程：

1. 从配置的 GitHub 仓库拉取最新代码。
2. 将新版本文件同步到网站目录。
3. 保留运行环境相关文件。
4. 完成后在后台检查系统状态。

更新时建议保留运行数据：

```text
config/database.php
data/
logs/
```

这样可以避免覆盖数据库配置、安装锁、运行日志等重要环境数据。

## 安全提醒

部署到公网前，请务必检查安全配置。

不要上传以下敏感内容：

```text
访问令牌文件
.env
logs/
数据库密码
支付接口密钥
邮箱授权码
私钥
真实用户隐私数据
真实订单卡密数据
```

建议：

- 关闭 PHP 错误直接输出
- 后台使用强密码
- 数据库账号只授予必要权限
- 定期备份数据库
- 定期检查 `logs/` 日志
- 不要将真实支付密钥提交到 GitHub
- 不要将真实卡密数据提交到 GitHub
- 给后台入口增加额外访问保护
- 生产环境开启 HTTPS

## 常见问题

### 为什么后台修改后刷新还是旧页面？

项目中可能存在多个后台入口文件，例如：

```text
admin/index.php
public/admin.php
public/admin/index.php
```

如果服务器实际访问的是 `public/admin/index.php`，只修改 `admin/index.php` 不会生效。需要确认当前域名绑定目录和实际访问入口，并同步对应文件。

### 游客为什么必须填写邮箱？

游客没有固定账号，如果只依赖当前浏览器缓存，换设备或清除缓存后可能无法找回订单。填写真实邮箱后，系统会发送查询码，游客可以通过邮箱和查询码找回卡密。

### 邮件没有收到怎么办？

请检查：

- 邮箱配置是否正确
- SMTP 授权码是否正确
- 服务器是否允许外发邮件
- 邮件是否进入垃圾箱
- 第三方邮件服务是否限制发送频率

### 批量卡密为什么使用一个文本框？

如果买家一次购买几十个或上百个卡密，多个小框会非常难复制和查看。统一使用一个只读文本框，一行一个卡密，更适合批量复制、保存和导出。

## 开发说明

如果需要继续开发，建议遵循以下规则：

- 重要业务数据优先保存到数据库
- 修改后台页面时同步多个后台入口
- 修改前台资源时同步 `assets/` 和 `public/assets/`
- 涉及订单、库存、余额的逻辑必须谨慎处理
- 涉及卡密、支付、邮箱密钥的内容不要写入公开仓库
- 新功能上线前先测试普通用户、游客、商家、管理员四种视角
